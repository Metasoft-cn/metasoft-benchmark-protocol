# Failure Corpus

## Principle

Failure cases before aggregate scores. A benchmark that reports only `accuracy = 92%` hides the failure modes. Two systems with the same accuracy can have very different failure distributions, and the distribution is what matters for understanding behavior.

## Required fields

Each failure record (see [`schemas/failure.schema.json`](../schemas/failure.schema.json)):

- `category` — the failure class.
- `case_id` — the triggering case.
- `expected` — the expected outcome.
- `actual` — the observed outcome.
- `severity` — `catastrophic` / `major` / `minor`.
- `reproduction` — a command or trace that reproduces the failure.
- `metric_impact` (optional) — which metric(s) this failure contributes to.

## Severity guidance

- **catastrophic** — the system did the wrong thing in a way that breaks the user's task (e.g. a wrong jump to a distant position, a hallucinated business claim, a temporal-leakage trade).
- **major** — a meaningful error that degrades the task but does not break it (e.g. a missed segment, an unsupported metric change).
- **minor** — a small deviation within tolerance (e.g. off-by-one recovered on the next event).

## Category examples by domain

| Domain | Example categories |
|---|---|
| speech-follow | `wrong_backward`, `false_jump_commit`, `stale_partial`, `lost_recovery` |
| interview-evaluation | `ranking_inconsistency`, `verbosity_drift`, `paraphrase_drift`, `evidence_ungrounded` |
| website-renovation | `unsupported_business_claim`, `content_omission`, `url_broken`, `seo_regression` |
| quant-strategy | `temporal_leakage`, `unrealistic_fill`, `pit_violation`, `regime_collapse` |

## Reporting

A results object SHOULD include:

- `failures.count` — total failures,
- `failures.categories` — a map of category → count,
- `failures.items` — the individual records (or a reference to a separate failure file for large corpora).

For very large failure corpora (CSFB's full failure file is ~24.5 MB), the failure file may be omitted from the release tree and regenerated by `run --full`, while a smaller `results.csv` preserves per-event predictions for inspection.

## CSFB reference

CSFB reports per-failure categories including `catastrophic_absolute`, `wrong_backward`, and `false_jump_commit`, partitioned by language and navigation strata. The full failure corpus is reproducible with `csfb run --full`; `csfb replay --case <id> --trace` reproduces a single case.
